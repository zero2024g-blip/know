# به‌روزرسانیِ پنل: تمدید کلیدها + صفحه‌ی Download خوش‌تم

دو چیز در این پوشه:

1. **بخشِ تمدید کلیدها** (ادمین) — کلید را با کد یا آیدی پیدا کن، وضعیتش را ببین
   (استفاده‌نشده / معتبر / منقضی)، و بهش زمان اضافه کن.
2. **صفحه‌ی Download بازطراحی‌شده** — دقیقاً هم‌تمِ پنل (ember، فونت Poppins، رنگِ مرجانی)،
   با visible شدنِ درستِ فایل‌ها (رایگان‌ها همیشه؛ قفل‌دارها بعد از زدنِ کلید).

هیچ‌کدام فایلِ موجودی را خراب نمی‌کند: `KeyRenew` یک کنترلر **جدید** است و صفحه‌ی
Download فقط `page.php` را جایگزین می‌کند.

```
panel-updates/
  app/Controllers/KeyRenew.php        ← جدید (کپی کن)
  app/Views/Keys/renew.php            ← جدید (کپی کن)
  app/Views/Download/page.php         ← جایگزینِ فایلِ فعلی
  app/Controllers/Download.php        ← اختیاری (فقط برای تیزرِ فایل‌های پولی)
  routes-add.php                      ← ۵ خط روت برای اضافه‌کردن
```

## بخش ۱ — تمدید کلیدها

### گام ۱: فایل‌ها را بگذار
```
app/Controllers/KeyRenew.php
app/Views/Keys/renew.php
```

### گام ۲: روت‌ها
پنج خطِ داخل `routes-add.php` را **درونِ گروهِ admin** در `app/Config/Routes.php`
بگذار (همان گروهی که `downloads`، `security`، `maintenance` داخلش است):
```php
$routes->get('keys/renew',                'KeyRenew::index');
$routes->post('keys/renew/lookup',        'KeyRenew::lookup');
$routes->post('keys/renew/apply',         'KeyRenew::apply');
$routes->post('keys/renew/bulk-preview',  'KeyRenew::bulkPreview');
$routes->post('keys/renew/bulk-apply',    'KeyRenew::bulkApply');
```
فیلترِ `admin` را به ارث می‌برند و کنترلر هم خودش دوباره سطحِ ادمین را چک می‌کند.

### گام ۳: لینک در منو + آیکون
در `app/Views/Layout/Header.php`، داخلِ منوی کشویی ادمین، **درست بعد از «Deleted Keys»**
(همان‌جا که گذاشتی) این `<li>` را بگذار — آیکونِ فلشِ چرخشی (`bi-arrow-clockwise`) دارد و
مثلِ بقیه‌ی آیتم‌ها حالتِ active هم می‌گیرد (فایلِ `header-menu-item.php` هم همین است):
```php
<li>
    <a class="dropdown-item <?= url_is('admin/keys/renew') ? 'active' : '' ?>" href="<?= site_url('admin/keys/renew') ?>">
        <i class="bi bi-arrow-clockwise"></i> Renew keys
    </a>
</li>
```
اگر «Renew keys» را بدونِ آیکون گذاشته بودی، فقط تگِ `<i class="bi bi-arrow-clockwise"></i> `
را قبل از متن اضافه کن.

### چطور کار می‌کند (فقط کلیدِ فعال + معتبر)
تمدید **فقط** روی کلیدی اعمال می‌شود که هر دو شرط را داشته باشد:
1. **فعال** است (`status = 1`)، و
2. هنوز **معتبر** است (`expired_date` در آینده).

> داشتنِ دستگاه **لازم نیست** — کلیدی که دستگاه‌هایش ریست شده باشد هم قابلِ تمدید است.

نتیجه: زمانش از **انتهای فعلیِ خودش** تمدید می‌شود (باقی‌مانده حفظ). برای هر حالتِ دیگر
**هیچ تغییری اعمال نمی‌شود** و دلیلش نمایش داده می‌شود:

| وضعیت | نتیجه |
|---|---|
| فعال + معتبر | ✅ تمدید (extend از انتهای فعلی) |
| **غیرفعال** (status=0) | ⛔ رد — «کلید غیرفعال است» |
| **استفاده‌نشده** (بدون انقضا، ساعت شروع‌نشده) | ⛔ رد — «هنوز شروع نشده» |
| **منقضی/تموم‌شده** | ⛔ رد — «کلید منقضی شده» |

- در صفحه، اگر کلیدِ غیرقابل‌تمدید را باز کنی، وضعیتش را می‌بینی ولی بخشِ «Add time» قفل و دلیل
  به‌صورتِ قرمز نشان داده می‌شود؛ دکمه‌ی Renew غیرفعال می‌ماند. سرور هم مستقل چک می‌کند
  (حتی اگر کسی مستقیم درخواست بفرستد، رد می‌شود).
- هر تمدید در جدولِ `history` ثبت می‌شود: `renew|extend|+<hours>h`.
- سقفِ یک‌بار تمدید: ۱۰ سال (جلوی اشتباهِ تایپی).
- دکمه‌های آماده: ۱روز، ۷، ۳۰، ۹۰، ۱۸۰ روز، ۱ سال — یا مقدارِ دلخواه (روز/ساعت).

### تمدیدِ دسته‌ای (Bulk) — «به همه‌ی کلیدهای فعال مثلاً ۳-۴ روز اضافه کن»
پایینِ همان صفحه یک پنلِ **Bulk renew** هست:
- **دامنه (scope):** همه‌ی بازی‌ها یا یک بازیِ خاص + (اختیاری) یک فروشنده (username).
- فقط کلیدهای **فعال + معتبر** لمس می‌شوند: `status=1` و `expired_date` در آینده.
  (داشتنِ دستگاه لازم نیست.) کلیدهای **غیرفعال، استفاده‌نشده، و منقضی** هرگز دست‌نخورده می‌مانند.
- روالِ امن: اول **Preview count** تعداد را نشان می‌دهد → بعد **Renew all** با یک
  دیالوگِ تأیید (SweetAlert). بدونِ `confirm` سرور چیزی را تغییر نمی‌دهد.
- موتور: یک `UPDATE` اتمیکِ واحد با `DATE_ADD(expired_date, INTERVAL N HOUR)` —
  برای هزاران کلید سریع است و هر کلید از **انتهای خودش** تمدید می‌شود (وقتِ باقی‌مانده حفظ).
- تعدادِ مقدار یک عددِ صحیحِ اعتبارسنجی‌شده است (بدون امکانِ تزریق)؛ سقف ۱۰ سال.
- یک خطِ خلاصه در لاگ ثبت می‌شود: `Bulk renew by <admin>: +Nh to M key(s), scope [...]`.

هیچ ستون یا جدولِ جدیدی لازم **نیست** (از همان `keys_code` و `history` استفاده می‌کند).

## بخش ۲ — صفحه‌ی Download

فایلِ view را جایگزین کن:
```
app/Views/Download/page.php
```
`page.php` **سازگارِ عقب‌رو** است: با کنترلرِ قدیمی هم کار می‌کند (بدونِ تیزر).

### نمایش / مخفی‌کردنِ فایل‌های پولی — دو سطحِ کنترل
**۱) هر فایل، جداگانه (همین الان موجود — مدیریتِ Downloads ادمین):**
- **Who can download:** `Free` (رایگان) یا `Key required` (پولی).
- **On the public download page:** `Listed` (روی صفحه دیده می‌شود) یا `Unlisted` (فقط با لینکِ مستقیم).
- **How it is delivered:** `Browser link` / `API` / `Both`. فایلِ `API-only` هیچ‌وقت روی صفحه نیست.

جدولِ رفتار:

| فایلِ پولی | نتیجه روی صفحه |
|---|---|
| Listed + Browser | نامش دیده می‌شود؛ **بعد از کلید** قابلِ دانلود (یا با تیزر، از قبل قفل‌دار) |
| Unlisted | روی صفحه **نیست**؛ فقط لینکِ مستقیم |
| API-only | هیچ‌وقت روی صفحه نیست |

**۲) حالتِ تیزرِ «Premium files» (جدید — سراسری):**
یک سوییچ در بالای `Download.php`:
```php
private const LIST_LOCKED_TEASER = true;   // نامِ فایل‌های پولی را قفل‌دار نشان بده
                                            // false = مخفی تا وقتی کلید زده شود
```
- **true:** فایل‌های پولیِ Listed به‌صورتِ یک لیستِ **قفل‌دار** («Key required») قبل از زدنِ کلید
  دیده می‌شوند تا بازدیدکننده بداند با کلید چه می‌گیرد. بعد از زدنِ کلیدِ معتبر، لیستِ قفل‌دار جمع
  می‌شود و لیستِ واقعیِ قابلِ‌دانلود ظاهر می‌شود.
- **false (پیش‌فرضِ خصوصی):** نامِ فایلِ پولی به غریبه لو نمی‌رود و فقط بعد از کلیدِ معتبر ظاهر می‌شود.
- کنترلِ هر فایل همچنان مقدم است: فایلِ Unlisted یا API-only در تیزر هم نشان داده نمی‌شود.

> اگر تیزر را می‌خواهی، فایلِ `app/Controllers/Download.php` را هم جایگزین کن (سوییچ رویش true است).
> اگر نمی‌خواهی، فقط `page.php` را بگذار و کنترلرِ خودت را نگه‌دار — فایل‌های پولی بعد از کلید ظاهر می‌شوند.

قرارداد و روت‌ها یکی است (`$free`, `$anyGated`, `$locked?`, و `download/get` و `download/unlock`).

### چه بهتر شد
- **هم‌تمِ سایت:** پالتِ ember، فونتِ Poppins و آیکون‌های bootstrap-icons از همان
  assetهای پنل (same-origin) لود می‌شوند؛ اگر لود نشدند، فونتِ سیستمی fallback است.
- **کارتِ فایل‌ها:** آیکون، pillِ بازی، حجم، دکمه‌ی گرادیانتیِ Get با اسپینرِ لودینگ.
- **رایگان‌ها همیشه دیده می‌شوند؛** قفل‌دارها فقط **بعد از زدنِ کلیدِ معتبر** ظاهر می‌شوند
  (نامِ فایلِ قفل‌دار هیچ‌وقت به کسی که کلید ندارد لو نمی‌رود — این رفتار از قبل در کنترلر بود).
- **حالتِ لودینگ (skeleton)** موقعِ باز کردنِ کلید، پیامِ خطا/موفقِ inline، حالتِ خالی.
- **کلید روی همان دستگاه ذخیره می‌شود** (`localStorage`) تا دفعه‌ی بعد لازم نباشد دوباره بزنی.
- **کپیِ لینکِ اشتراکیِ** فایلِ رایگان (به `download/direct/<slug>`) با یک toast.
- ریسپانسیو، safe-area، فوکوسِ کیبورد، و احترام به `prefers-reduced-motion`.

### تست
```
https://panel.zeromods.id/download
```
- بدون لاگین باز می‌شود (در `except`ِ auth و csrf است).
- فایل رایگان → مستقیم Get.
- کلید بزن → فقط فایل‌هایی که آن کلید بازشان می‌کند ظاهر می‌شوند.

> نکته: اگر صفحه‌ی Download را برای اولین‌بار راه می‌اندازی، مطمئن شو مدل‌ها/جدولِ
> `download_files`, `download_tokens`, `download_ratelimit` از `MIGRATION.sql` ساخته شده‌اند
> (اینها ربطی به بخشِ تمدید ندارند).
