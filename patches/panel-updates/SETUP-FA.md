# به‌روزرسانیِ پنل: تمدید کلیدها + صفحه‌ی Download خوش‌تم

دو چیز در این پوشه:

1. **بخشِ تمدید کلیدها** (ادمین) — کلید را با کد یا آیدی پیدا کن، وضعیتش را ببین
   (استفاده‌نشده / معتبر / منقضی)، و بهش زمان اضافه کن.
2. **صفحه‌ی Download بازطراحی‌شده** — دقیقاً هم‌تمِ پنل (ember، فونت Poppins، رنگِ مرجانی)،
   با visible شدنِ درستِ فایل‌ها (رایگان‌ها همیشه؛ قفل‌دارها بعد از زدنِ کلید).

هیچ‌کدام فایلِ موجودی را خراب نمی‌کند: `KeyRenew` یک کنترلر **جدید** است و صفحه‌ی
Download فقط `page.php` را جایگزین می‌کند.

```
panel-updates/
  app/Controllers/KeyRenew.php        ← جدید (کپی کن)
  app/Views/Keys/renew.php            ← جدید (کپی کن)
  app/Views/Download/page.php         ← جایگزینِ فایلِ فعلی
  routes-add.php                      ← ۳ خط روت برای اضافه‌کردن
```

## بخش ۱ — تمدید کلیدها

### گام ۱: فایل‌ها را بگذار
```
app/Controllers/KeyRenew.php
app/Views/Keys/renew.php
```

### گام ۲: روت‌ها
پنج خطِ داخل `routes-add.php` را **درونِ گروهِ admin** در `app/Config/Routes.php`
بگذار (همان گروهی که `downloads`، `security`، `maintenance` داخلش است):
```php
$routes->get('keys/renew',                'KeyRenew::index');
$routes->post('keys/renew/lookup',        'KeyRenew::lookup');
$routes->post('keys/renew/apply',         'KeyRenew::apply');
$routes->post('keys/renew/bulk-preview',  'KeyRenew::bulkPreview');
$routes->post('keys/renew/bulk-apply',    'KeyRenew::bulkApply');
```
فیلترِ `admin` را به ارث می‌برند و کنترلر هم خودش دوباره سطحِ ادمین را چک می‌کند.

### گام ۳: لینک در منو (اختیاری، توصیه‌شده)
در `app/Views/Layout/Header.php`، داخلِ منوی کشویی ادمین (کنارِ «Deleted Keys»)
این را اضافه کن:
```php
<li>
    <a class="dropdown-item <?= url_is('admin/keys/renew') ? 'active' : '' ?>" href="<?= site_url('admin/keys/renew') ?>">
        <i class="bi bi-arrow-clockwise"></i> Renew keys
    </a>
</li>
```

### چطور کار می‌کند (منطقِ «معتبر / مصرف‌شده»)
کلید سه حالت دارد و برای هرکدام کارِ درست انجام می‌شود:

| وضعیت | معنی | تمدید چه می‌کند |
|---|---|---|
| **Unused** (`expired_date` خالی) | هنوز فعال نشده؛ ساعتش با اولین لاگین شروع می‌شود | به **duration** اضافه می‌کند (وقتِ فعال‌سازی طولانی‌تر می‌شود) |
| **Active** (`expired_date` در آینده) | معتبر | از **انتهای فعلی** تمدید می‌کند (وقتِ باقی‌مانده از بین نمی‌رود) |
| **Expired** (`expired_date` گذشته) | مصرف‌شده | از **الان** ری‌استارت می‌کند (now + مدت) و کلید را **دوباره فعال** می‌کند (status=1) |

- تیکِ «Re-activate» فقط برای کلیدِ بلاک/منقضی نشان داده می‌شود و به‌صورت پیش‌فرض روشن است.
- هر تمدید در جدولِ `history` ثبت می‌شود: `renew|<mode>|+<hours>h`.
- سقفِ یک‌بار تمدید: ۱۰ سال (جلوی اشتباهِ تایپی).
- دکمه‌های آماده: ۱روز، ۷، ۳۰، ۹۰، ۱۸۰ روز، ۱ سال — یا مقدارِ دلخواه (روز/ساعت).

### تمدیدِ دسته‌ای (Bulk) — «به همه‌ی کلیدهای معتبر مثلاً ۳-۴ روز اضافه کن»
پایینِ همان صفحه یک پنلِ **Bulk renew** هست:
- **دامنه (scope):** همه‌ی بازی‌ها یا یک بازیِ خاص + (اختیاری) یک فروشنده (username).
- فقط کلیدهای **معتبر/فعال** لمس می‌شوند: `status=1` و `expired_date` در آینده.
  کلیدهای **استفاده‌نشده** و **منقضی** دست‌نخورده می‌مانند (آنها را تک‌به‌تک بالا تمدید کن).
- روالِ امن: اول **Preview count** تعداد را نشان می‌دهد → بعد **Renew all** با یک
  دیالوگِ تأیید (SweetAlert). بدونِ `confirm` سرور چیزی را تغییر نمی‌دهد.
- موتور: یک `UPDATE` اتمیکِ واحد با `DATE_ADD(expired_date, INTERVAL N HOUR)` —
  برای هزاران کلید سریع است و هر کلید از **انتهای خودش** تمدید می‌شود (وقتِ باقی‌مانده حفظ).
- تعدادِ مقدار یک عددِ صحیحِ اعتبارسنجی‌شده است (بدون امکانِ تزریق)؛ سقف ۱۰ سال.
- یک خطِ خلاصه در لاگ ثبت می‌شود: `Bulk renew by <admin>: +Nh to M key(s), scope [...]`.

هیچ ستون یا جدولِ جدیدی لازم **نیست** (از همان `keys_code` و `history` استفاده می‌کند).

## بخش ۲ — صفحه‌ی Download

فقط این فایل را جایگزین کن:
```
app/Views/Download/page.php
```
کنترلرِ `Download.php` و روت‌هایش **دست‌نخورده** می‌مانند — قرارداد یکی است
(`$free`, `$anyGated`, و اندپوینت‌های `download/get` و `download/unlock`).

### چه بهتر شد
- **هم‌تمِ سایت:** پالتِ ember، فونتِ Poppins و آیکون‌های bootstrap-icons از همان
  assetهای پنل (same-origin) لود می‌شوند؛ اگر لود نشدند، فونتِ سیستمی fallback است.
- **کارتِ فایل‌ها:** آیکون، pillِ بازی، حجم، دکمه‌ی گرادیانتیِ Get با اسپینرِ لودینگ.
- **رایگان‌ها همیشه دیده می‌شوند؛** قفل‌دارها فقط **بعد از زدنِ کلیدِ معتبر** ظاهر می‌شوند
  (نامِ فایلِ قفل‌دار هیچ‌وقت به کسی که کلید ندارد لو نمی‌رود — این رفتار از قبل در کنترلر بود).
- **حالتِ لودینگ (skeleton)** موقعِ باز کردنِ کلید، پیامِ خطا/موفقِ inline، حالتِ خالی.
- **کلید روی همان دستگاه ذخیره می‌شود** (`localStorage`) تا دفعه‌ی بعد لازم نباشد دوباره بزنی.
- **کپیِ لینکِ اشتراکیِ** فایلِ رایگان (به `download/direct/<slug>`) با یک toast.
- ریسپانسیو، safe-area، فوکوسِ کیبورد، و احترام به `prefers-reduced-motion`.

### تست
```
https://panel.zeromods.id/download
```
- بدون لاگین باز می‌شود (در `except`ِ auth و csrf است).
- فایل رایگان → مستقیم Get.
- کلید بزن → فقط فایل‌هایی که آن کلید بازشان می‌کند ظاهر می‌شوند.

> نکته: اگر صفحه‌ی Download را برای اولین‌بار راه می‌اندازی، مطمئن شو مدل‌ها/جدولِ
> `download_files`, `download_tokens`, `download_ratelimit` از `MIGRATION.sql` ساخته شده‌اند
> (اینها ربطی به بخشِ تمدید ندارند).
